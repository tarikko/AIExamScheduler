Analytical Notes

Hard constraints
  • No room-timeslot can host two exams.
  • No student can sit two exams at the same timeslot.
  • Assigned rooms must fit exam enrollment.
Metrics
  • Stress counts consecutive exams for students on the same day.
  • Room load counts how many exams each room hosts per day.
  • Exports include assignments and generated metrics.

Algorithm Guide

Greedy Search

Greedy is the fastest baseline. It sorts exams by how difficult they are to place, then commits each exam to the best valid room-timeslot available at that moment.

  • Uses conflict degree and enrolment size to schedule harder exams first.
  • Prefers valid slots with lower same-day student stress and tighter room fit.
  • Expected to return quickly, even on larger benchmarks.
  • Not expected to recover from a bad early choice because it does not backtrack.

CSP

CSP treats timetabling as a constraint satisfaction problem. It searches through possible assignments while pruning values that would break hard constraints.

  • Uses Minimum Remaining Values to choose the most constrained exam next.
  • Uses forward checking to remove invalid room-timeslots from remaining exams.
  • Expected to produce strong feasible schedules on smaller or moderately constrained data.
  • Not expected to fully prove optimality when the time limit is reached.

A* Search

A* explores partial schedules with a priority queue. It expands assignments that look promising according to current cost and remaining scheduling difficulty.

  • Uses conflict density, room fit, late-slot cost, and soft-stress estimates.
  • Keeps a greedy fallback so a partial search can still return a usable result.
  • Expected to be more deliberate than Greedy while staying bounded by time.
  • Not expected to exhaustively search large benchmarks.

Genetic Algorithm

The Genetic Algorithm evolves many candidate schedules. It uses selection, crossover, mutation, elitism, and cached fitness scoring to improve schedules across generations.

  • Uses a greedy seed and mutated variants on small and medium datasets.
  • Uses adaptive population, generation, and time caps for large benchmarks.
  • Expected to act as an improvement pass rather than an exact solver.
  • Not expected to guarantee the best possible timetable.

How To Compare Results

Use Greedy when

You need a fast baseline, want quick feedback after upload, or are checking whether the dataset can be scheduled at all.

Use CSP when

You want stronger hard-constraint reasoning and can accept a bounded backtracking search.

Use A* when

You want guided search over partial schedules with a balance between speed and exploration.

Use GA when

You want a heuristic improvement pass and can accept stochastic results that may vary between runs.

A feasible schedule has zero hard violations. After that, compare stress load, room daily load, fitness, and runtime to decide which result is better for your planning needs.
